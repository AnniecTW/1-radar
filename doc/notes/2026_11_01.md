# Changes to Date — 2026-11-01

## PRD

- Clarified draft publishing requirements and the account anonymization procedure in `Radar_PRD.md`.

## Data models and migrations

- Added organization roles `Owner`, `Admin`, and `Check-in Staff`; new organizations automatically give ownership to their creator. Added database rules requiring exactly one Owner and rejecting invalid roles.
- Normalized primary and campus emails to lowercase, added case-insensitive uniqueness, and kept email login case-insensitive.
- Automatically generated `user_<UUID>` usernames when regular accounts are saved without one; administrator-created superusers can still set usernames manually.
- Aligned the custom User model options and `EventCheckInStaff` primary key with their existing migrations; no new migration was needed.
- Made event draft title, slug, and dates optional; added publish validation and automatic unique slug generation.
- Added event contact/cancellation fields and event-level Check-in Staff assignments.
- Added RSVP `interested` status and `waitlisted_at`; added outbound-click records, waitlist notification types, and daily Interested/outbound-click counters.
- Added database capacity guards and ticket/check-in event consistency guards.
- Added RSVP services for placing/cancelling RSVPs, capacity changes, FIFO waitlist promotion, ticket issuance, and waitlist notices.
- Added role-based permission helpers and guarded services for organization membership/ownership, event creation/editing/publishing/cancellation, staff assignment, RSVP capacity, check-in, analytics, exports, and reports. Removed direct Django Admin access to attendee RSVP, ticket, check-in, follower, outbound-click, and analytics records.
- Added permission and check-in service tests, plus a repeatable `seed_mock_data` management command for a small demo dataset. README now documents how to run it safely.

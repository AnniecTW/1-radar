| AI model / technique                               | Text embeddings with `@cf/baai/bge-small-en-v1.5` (BGE small, 384 dimensions) called through the Cloudflare Workers AI API. Results are ranked by cosine similarity in PostgreSQL with pgvector and an HNSW index.                                                                                                                                                                                                                                                                                                                                                                                                                 | **Current:** rule-based. Upcoming events that match at least one of the user's interests.<br>**Planned:** content-based ranking that reuses the BGE small event embeddings from Semantic Search. A user profile vector is the weighted average of the embeddings of events the user saved, liked, RSVP'd to, or viewed. Upcoming events are ranked by cosine similarity to that vector with pgvector, blended with popularity.                                                                                                          | Vision model `@cf/moondream/moondream3.1-9B-A2B` (Moondream 3.1) on Cloudflare Workers AI, `query` task with `stream: true` last. The prompt asks for JSON only with separate `date`, `start_time`, `end_time` fields plus `title, description, location_text, organizer, price, registration_url, categories[]`. Code then parses dates against the campus time zone, fuzzy-matches venues, and maps categories to the interest list.                                                                                                                                                                                                                                                                                                                                                                                                      |
| Input / Output                                     | **Input:** a natural-language query from the search bar. Events below a minimum similarity of 0.58 are left out.                                                                                                                                                                                                                                                                                                           | **Input:** the user's chosen interests and their activity history.<br>**Output:** up to 10 upcoming events in the "Recommended for you" carousel on the homepage.                                                                                                                                                                                                                                                                                                                                                                       | **Input:** a flyer photo or upload (JPG/PNG/HEIC or the first page of a PDF, ≤ 10 MB) from a campus-verified host.<br>**Output:** a pre-filled event draft shown beside the flyer on a review screen, with a per-field confidence computed in code (not by the model). Planned: signals on save, like, and RSVP refresh the user's profile vector.                                                                 | **Database** (already in place): `FlyerUpload` in `apps/flyers/models.py` stores the image path and other event details. Events created this way get `Event.source = flyer_ai`. <br/> **Config**: reuses `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN`, plus a new `CLOUDFLARE_VISION_MODEL` setting in `.env`. <br/> **Codebase** (planned): `upload_flyer` (`POST /api/flyers/`) saves the image to S3-compatible storage via django-storages and queues a Celery task (Redis broker, not yet installed). `get_flyer_extraction_status` (`GET /api/flyers/{id}/`) is polled by the review page via HTMX every 2 s. | Risk Control / Guardrail                           | **Graceful fallback:** if Cloudflare is unconfigured, times out (5 s, one retry), or errors, the page shows keyword results with the notice "AI search is temporarily unavailable."<br>**Output validation:** every vector must have exactly 384 finite values, or it is rejected.<br>**Privacy:** the search box tells users not to enter personal or sensitive information. Query text is never logged; only event IDs and scores are logged for tuning.<br>**Input limits:** queries are capped at 100 characters and event text at 5,000 characters. A failed embedding never blocks saving an event and can be rebuilt later. | **Privacy:** the profile vector is built from event embeddings already in the database, so no personal data is sent to Cloudflare. Personalization is disclosed in the Privacy Policy accepted at signup.<br>**Sensitive interests:** events that could reveal religion, sexuality, health, or politics are left out of the profile unless the user opts in.<br>**User control:** users can mark events "Not interested", turn off activity-based recommendations, or clear their history; account deletion removes the profile vector. | **Human review:** AI output is never published without host confirmation. Fields that fail code checks are highlighted, and missing required fields in red. The model's self-reported confidence is ignored.<br>**Output validation:** Pydantic rejects malformed JSON; dates are normalized against the upload date and campus time zone.<br>**Graceful fallback:** up to 2 retries with a 30 s timeout; on failure the host gets the manual form with the flyer attached.<br>**Cost and abuse limits:** 10 extractions per user per day; campus-verified hosts only, with file type and size checks.<br>**Privacy:** Cloudflare lists zero data retention for this model.<br>**Content safety:** uploaded images pass moderation before public listing.<br>**Observability:** raw responses, latency, token usage, and errors are logged. |

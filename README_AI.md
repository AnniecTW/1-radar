| AI model / technique                               | Text embeddings with `@cf/baai/bge-small-en-v1.5` (BGE small, 384 dimensions) called through the Cloudflare Workers AI API. Results are ranked by cosine similarity in PostgreSQL with pgvector and an HNSW index.                                                                                                                                                                                                                                                                                                                                                                                                                 | **Current:** rule-based. Upcoming events that match at least one of the user's interests.<br>**Planned:** content-based ranking that reuses the BGE small event embeddings from Semantic Search. A user profile vector is the weighted average of the embeddings of events the user saved, liked, RSVP'd to, or viewed. Upcoming events are ranked by cosine similarity to that vector with pgvector, blended with popularity.                                                                                                          | Vision model `@cf/moondream/moondream3.1-9B-A2B` (Moondream 3.1) on Cloudflare Workers AI, `query` task with `stream: true` (without it Cloudflare returns an empty result), reasoning off and temperature 0. Live test on 7 real campus flyers (Nov 15 2026): 7/7 valid JSON; about 880 input and 150 output tokens (≈ 38 Neurons, so the free 10,000 Neurons/day cover ~260 flyers) and 1.7–3.5 s per flyer (average 2.9 s); 40 of 42 required form fields filled after cleanup; 4 of 7 locations matched to a campus building (the other 3 were a city, the whole university and a time zone). The prompt asks for JSON only with separate `date`, `start_time`, `end_time` fields plus `title, description, location_text, organizer, price, registration_url, categories[]`. Code then parses dates against the campus time zone, fuzzy-matches venues, and maps categories to the interest list.                                                                                                                                                                                                                                                                                                                                                                                                      |

| Risk Control / Guardrail                           | **Graceful fallback:** if Cloudflare is unconfigured, times out (5 s, one retry), or errors, the page shows keyword results with the notice "AI search is temporarily unavailable."<br>**Output validation:** every vector must have exactly 384 finite values, or it is rejected.<br>**Privacy:** the search box tells users not to enter personal or sensitive information. Query text is never logged; only event IDs and scores are logged for tuning.<br>**Input limits:** queries are capped at 100 characters and event text at 5,000 characters. A failed embedding never blocks saving an event and can be rebuilt later. | **Privacy:** the profile vector is built from event embeddings already in the database, so no personal data is sent to Cloudflare. Personalization is disclosed in the Privacy Policy accepted at signup.<br>**Sensitive interests:** events that could reveal religion, sexuality, health, or politics are left out of the profile unless the user opts in.<br>**User control:** users can mark events "Not interested", turn off activity-based recommendations, or clear their history; account deletion removes the profile vector. | **Human review:** AI output is never published without host confirmation. Fields that fail code checks are highlighted, and missing required fields in red. The model's self-reported confidence is ignored.<br>**Output validation:** code rejects answers that aren't a JSON object and keeps only the expected keys; dates are resolved against the upload date in the campus time zone (no year printed → the next matching date; a weekday that doesn't match the date lowers confidence); venues are matched to Radar's campus building list, including the short names on flyers (SDRP, ECEB, BIF, "Smith Music Hall"; loaded with `seed_campus_buildings` from the Facilities & Services building list), and categories to Radar's own list.<br>**Graceful fallback:** one retry on network or server errors, 25 s timeout; on failure the host gets the manual form with the flyer attached as the cover.<br>**Cost and abuse limits:** 10 extractions per user per day; campus-verified hosts only, with file type and size checks.<br>**Privacy:** Cloudflare lists zero data retention for this model.<br>**Content safety (planned):** moderation of uploaded images before public listing.<br>**Observability:** the raw answer, latency and any error are stored on each `FlyerUpload`.<br>**Known limitations (from the 7-flyer test):** places not in the campus building list (`apps/venues/campus_buildings.py`) stay as text and are flagged for the host; events that end after midnight lose their end time, because the event form needs the end on the same day; the model occasionally misreads characters (a stray "£" in one title) or returns topic words that fit none of Radar's categories; HEIC and PDF flyers aren't accepted yet. |

| AI model / technique                               | Text embeddings with `@cf/baai/bge-small-en-v1.5` (BGE small, 384 dimensions) called through the Cloudflare Workers AI API. Results are ranked by cosine similarity in PostgreSQL with pgvector and an HNSW index.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Content-based + popularity hybrid (PRD §3.8) that reuses the BGE small embeddings from Semantic Search. A user profile vector is the weighted average of the vectors of events the user acted on and of the interests they chose. Weights: check-in 5, RSVP 4 (going, waitlisted and interested alike), save 3, like 2, view 1 (at most 2 per event, and only views before a stronger action; a cancelled RSVP counts as a view), chosen interest 3. Actions lose half their weight every 30 days, and only the last 180 days are read. Interests are embedded from an internal description (e.g. "Music: concerts, open mics, jam sessions…"), not the one-word name. Upcoming events are scored in one PostgreSQL query: 0.45 × cosine similarity (pgvector) + 0.15 × follows the host + 0.15 × popularity + 0.15 × proximity (PostGIS distance) + 0.10 × starts within 14 days. No category takes more than 4 of the 10 slots. The prompt asks for JSON only with separate `date`, `start_time`, `end_time` fields plus `title, description, location_text, organizer, price, registration_url, categories[]`. Code then parses dates against the campus time zone, fuzzy-matches venues, and maps categories to the interest list.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

| Risk Control / Guardrail                           | **Graceful fallback:** if Cloudflare is unconfigured, times out (5 s, one retry), or errors, the page shows keyword results with the notice "AI search is temporarily unavailable."<br>**Output validation:** every vector must have exactly 384 finite values, or it is rejected.<br>**Privacy:** the search box tells users not to enter personal or sensitive information. Searches are logged anonymously to `SearchQueryLog` for tuning: no user is stored, email addresses and numbers of nine or more digits are blanked out, and rows are deleted after 180 days. The search box says so. Each row keeps the shown event IDs with their similarity scores and which result was opened first.<br>**Input limits:** queries are capped at 100 characters and event text at 5,000 characters. A failed embedding never blocks saving an event and can be rebuilt later. | **Privacy:** the profile vector is built from vectors already in the database, so nothing about the user is sent to Cloudflare. Location is asked for only after the user taps Share, and never if they chose "Don't use my location" on Account & privacy (also reachable from the banner's "Don't ask again"). The browser snaps it to a grid of about 500 m before sending, so the exact position never leaves the device. It is kept in a signed, HttpOnly cookie on the user's device (never the database) that expires after six hours and is ignored if another account signs in on the same browser. One shared location serves the whole app: the Explore Map opens on it (drawn as an approximate-location circle), and the map's crosshair and 15-minute walk filter use the same snapped location (the server snaps the walk filter's coordinates again) and share it for recommendations too. After "Not now" or a block in the browser, a "Use my location" button in the Recommended heading lets users change their mind, and a block explains how to allow location in the browser's settings. With location off, those two map controls are greyed out, with a hint that points to Account & privacy. Personalization is disclosed in the Privacy Policy accepted at signup.<br>**Graceful fallback:** without vectors, the row falls back to upcoming events tagged with the user's interests; with no interests and no activity, it asks the user to pick some instead of repeating Trending. Without a shared location, proximity's weight is spread over the other parts.<br>**Honest reasons:** "Similar to …" appears only above a cosine similarity of 0.8, because related-looking pairs on real data scored 0.58–0.69.<br>**Not interested (FR-43):** a dismissed event leaves the row until it ends, with an 8-second Undo. Events with a similarity above 0.75 to it lose up to 0.2 of their score (full at 0.90, so repeats of a series drop out of the top 10), taking the largest penalty when near several dismissals, fading with a 30-day half-life. Its views, likes and cancelled RSVPs from before the dismissal stop shaping the profile; anything after it counts again, and saves, RSVPs and check-ins always count.<br>**Clear recommendation history:** on Account & privacy, with a confirm dialog and a 10-minute Undo. It saves a reset time rather than deleting anything: activity and "Not interested" marks before it are ignored, so recommendations start over from the user's interests and follows.<br>**Planned:** a list of hidden events to undo later.<br>**Known limitation:** events that could reveal religion, health or politics (for example Faith, Activism and some Wellness events) shape the profile like any other event. A rule that ignored them unless the user had picked that interest was considered and set aside for now: it would also throw away ordinary signals, such as yoga for someone who never picked Wellness. | **Human review:** AI output is never published without host confirmation. Fields that fail code checks are highlighted, and missing required fields in red. The model's self-reported confidence is ignored.<br>**Output validation:** code rejects answers that aren't a JSON object and keeps only the expected keys; dates are resolved against the upload date in the campus time zone (no year printed → the next matching date; a weekday that doesn't match the date lowers confidence); venues are matched to Radar's campus building list, including the short names on flyers (SDRP, ECEB, BIF, "Smith Music Hall"; loaded with `seed_campus_buildings` from the Facilities & Services building list), and categories to Radar's own list.<br>**Graceful fallback:** one retry on network or server errors, 25 s timeout; on failure the host gets the manual form with the flyer attached as the cover.<br>**Cost and abuse limits:** 10 extractions per user per day; campus-verified hosts only, with file type and size checks.<br>**Privacy:** Cloudflare lists zero data retention for this model.<br>**Content safety (planned):** moderation of uploaded images before public listing.<br>**Observability:** the raw answer, latency and any error are stored on each `FlyerUpload`.<br>**Known limitations (from the 7-flyer test):** places not in the campus building list (`apps/venues/campus_buildings.py`) stay as text and are flagged for the host; events that end after midnight lose their end time, because the event form needs the end on the same day; the model occasionally misreads characters (a stray "£" in one title) or returns topic words that fit none of Radar's categories; HEIC and PDF flyers aren't accepted yet. |
